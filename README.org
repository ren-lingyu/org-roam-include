#+TITLE: Org Roam Include
#+AUTHOR: aRenCoco

* Overview
Org-roam-include is an experimental Emacs package for composing larger Org
documents from independent Org-roam nodes.

The package is intended to support an export-only include mechanism based on
stable Org-roam IDs.  A document can keep its own outline structure while
pulling each mounted headline's body from another Org-roam node.

Example target syntax:

#+BEGIN_SRC org
  ** Chapter title
     :PROPERTIES:
     :ROAM_INCLUDE: 00000000-0000-0000-0000-000000000000
     :END:
#+END_SRC

The local headline remains the exported heading.  The referenced Org-roam node
provides the body and any internal child headlines.

* Current Status
This repository is a development workspace.  It is expected to be rebuilt after
the feature semantics become stable.

The current implementation provides package metadata, dependency declarations,
user options, variable diagnostics, a global mode, and the first export-only
compilation path.

The first implementation compiles =ROAM_INCLUDE= properties in the current
export buffer to native Org =#+INCLUDE= keywords.  It intentionally does not
compile =ROAM_INCLUDE= properties inside files that are later pulled in by
Org's native include expander.

Only mounts present in the original export buffer are compiled.  A mounted
headline acts as a replacement mount point: its local body and child subtrees
are removed from the export copy before the generated include is inserted.

* Goals
** Export-only behavior
The first stable target is export support.  The package should transform Org's
export temporary buffer before Org parses it, then let Org export continue as
usual.

The source Org files must not be modified.

** Stable user-facing references
The user-facing reference should be an Org-roam node ID, not a file path,
headline title, line number, or whether the node is stored as a file node or a
headline node.

** Local outline controls document structure
The composition document's local headline should define:

- exported title
- headline level
- order
- outline structure

The included node should provide only the mounted content body.

** Depend on stable extension points
The preferred integration point is:

#+BEGIN_SRC emacs-lisp
  org-export-before-processing-functions
#+END_SRC

This hook runs in Org's export temporary buffer before parsing.  It is a better
fit for this package than advising Org's internal include expander.

* Non-goals
The first implementation should not provide:

- editing-time preview
- inline overlay display
- link navigation enhancements
- =#+INCLUDE: "id:UUID"= syntax
- arbitrary Org include parameter forwarding
- a full reimplementation of Org's native include system

These may be revisited after the export-only path is reliable.

* Design Decisions
** Compile to native =#+INCLUDE=
Mounted nodes are compiled into native Org include forms before Org parses the
export buffer.

Headline nodes are compiled to native Org include locations based on the line
recorded by Org-roam:

#+BEGIN_SRC org
  #+INCLUDE: "/absolute/path/to/node.org::137" :only-contents t
#+END_SRC

File nodes have no direct native =:only-contents= equivalent, so they are
compiled to a native include with a package-defined body start:

#+BEGIN_SRC org
  #+INCLUDE: "/absolute/path/to/node.org" :lines "10-"
#+END_SRC

Line numbers are never persisted by users.  They are derived during export
from:

- =org-roam-node-file=
- =org-roam-node-point=
- =org-roam-node-level=

This avoids title-based headline search and keeps the exported include tied to
the resolved Org-roam ID.

The generated file-node =:lines= range uses Org's open-ended form: the start
line is included and the body continues to the end of the file.

Org-roam's database is the authority for node location.  Org-roam-include uses
the node file, level, and point recorded by org-roam.  If the recorded position
is outside the saved source file, or a headline node position no longer points
at a headline, export fails and the user should run =org-roam-db-sync=.

** Remove the source node shell
For a headline node, the generated include uses =:only-contents t=.  The local
mounting headline provides the exported heading shell, while Org's native
include expander excludes the source headline, planning information, and root
property drawer.

For example, this source node:

#+BEGIN_SRC org
  * Source title
    :PROPERTIES:
    :ID: source-id
    :END:

  Intro.

  ** Child section
  Text.
#+END_SRC

mounted here:

#+BEGIN_SRC org
  ** Local title
     :PROPERTIES:
     :ROAM_INCLUDE: source-id
     :END:
#+END_SRC

is compiled in the export temporary buffer as:

#+BEGIN_SRC org
  ** Local title

  #+INCLUDE: "/absolute/path/to/source.org::12" :only-contents t
#+END_SRC

Org then expands the include during its normal export processing.

Any existing local body or child subtrees under =Local title= are replaced in
the export copy.

Nested =ROAM_INCLUDE= mounts inside another replacement mount are ignored,
because the parent mount removes that local subtree from the export copy.

If a referenced file node has no body after file metadata, the local mounting
headline is kept and no =#+INCLUDE= keyword is inserted.  Headline node body
emptiness is left to Org's native include handling.

** File node metadata
For file nodes, file-level property drawers and a conservative set of leading
document metadata keywords are excluded from the mounted body.

The metadata keywords currently treated as file-node metadata are:

- =AUTHOR=
- =DATE=
- =DESCRIPTION=
- =FILETAGS=
- =LANGUAGE=
- =OPTIONS=
- =PROPERTY=
- =ROAM_ALIASES=
- =ROAM_REFS=
- =STARTUP=
- =TITLE=

Affiliated keywords such as =NAME=, =CAPTION=, and =ATTR_*= are not treated as
file metadata by this rule.

This means the mounted body does not inherit source-file document settings such
as =#+OPTIONS= or =#+PROPERTY=.  The composition document remains responsible
for its own document-level export environment.

** Relative file links
Because the first implementation delegates the actual include expansion to Org,
relative path behavior should stay close to native Org include behavior.
Org-roam-include does not currently expose link rewriting controls.

** Recursion and cycles
The first implementation does not compile =ROAM_INCLUDE= properties inside
included files.  It only compiles the export buffer that triggered
=org-export-before-processing-functions=.

The package option =org-roam-include-max-depth= is reserved for recursive
support.  It is validated when the mode is enabled but is not consumed by the
version 0.0.1 expansion algorithm.

Recursive support likely requires a thin advice around Org's include expansion
function or another stable hook around recursive include processing.  This is
left for a later phase.

* Implementation Plan
** Phase 1: Package skeleton
- Add standard package header.
- Declare dependencies on =org=, =ox=, =org-roam=, =rx=, and =subr-x=.
- Add =defgroup= and initial =defcustom= variables.
- Add =org-roam-include--variable-type-alist= and variable diagnostics in the
  style of =org-roam-organize--check-variables=.
- Add global =org-roam-include-mode=.
- Install an export preprocessor hook through
  =org-export-before-processing-functions=.

** Phase 2: Node resolution
- Resolve =ROAM_INCLUDE= property values with =org-roam-node-from-id=.
- Read =org-roam-node-file=, =org-roam-node-point=, and
  =org-roam-node-level=.
- Treat org-roam's database location as authoritative.
- Fail clearly when the database position is invalid and suggest
  =org-roam-db-sync=.
- Report missing IDs with enough context to identify the mounting headline.

** Phase 3: Content extraction
- Compile headline nodes to native =FILE::LINE= include locations with
  =:only-contents t=.
- Compute file node body start lines.
- Do not fall back to title-based headline search.
- Use =expand-file-name= rather than =file-truename= so logical symlink paths
  are preserved.
- Treat only selected leading document keywords as file-node metadata.

** Phase 4: Buffer expansion
- Scan the export temporary buffer for mounting headlines.
- Replace each mounted headline body with a generated native =#+INCLUDE=.
- Let Org derive included headline levels from the include position.
- Remove export-only =ROAM_INCLUDE= metadata from the temporary result.
- Respect the current export narrowing.
- Skip COMMENT subtrees.
- Ignore nested mounts inside another replacement mount.

This phase has a first implementation.

** Phase 5: Recursion and diagnostics
- Investigate recursive compilation of included files.
- Prefer a very small advice or a stable Org include hook if available.
- Improve error messages for missing files, missing nodes, malformed mounted
  headlines, and unreliable headline targets.

** Phase 6: Link handling
- Verify relative path behavior against Org's native include implementation.
- Add explicit link rewriting only if native include delegation is insufficient.

* Requirements
- Emacs 31.0 or later
- Org mode
- Org-roam 2.0.0 or later

* Configuration
During development the package can be loaded directly:

#+BEGIN_SRC emacs-lisp
  (load-file "~/Projects/org-roam-include/org-roam-include.el")
  (org-roam-include-mode 1)
#+END_SRC

After the package stabilizes, it should be usable with a normal =load-path= or
package manager setup.

Use the diagnostic command to inspect the current configuration:

#+BEGIN_SRC emacs-lisp
  (org-roam-include-check-variables)
#+END_SRC

* Development Notes
This repository intentionally prioritizes development convenience over clean
release history.  Intermediate commits do not need to be independently
complete or release-ready.

The stable boundary to preserve during development is behavioral: source Org
files should not be changed by export expansion.  All document composition
should happen in Org export temporary buffers.
